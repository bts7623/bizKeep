# OCR 파서 보완 계획 (2026-10-23)

실기기 등록 7장 중 이름을 맞춘 건 1장(곽영준). 원인은 OCR이 아니라 **분류 규칙**이다 — 텍스트는 거의 다 읽힘.
픽스처: `test/fixtures/cards/*.jpg` + `expected.json` (기대값·as-is·메모).

## 0. 준비: 실제 OCR 원문을 테스트에 쓰기
- 맥에서도 Vision이 돌아간다. `tools/ocr_fixtures.swift` 로 픽스처 사진을 OCR → `test/fixtures/cards/<name>.txt` 생성.
  `swift tools/ocr_fixtures.swift test/fixtures/cards` (데몬 큐로 실행)
- `test/ocr_parser_test.dart` 에 픽스처 루프 추가: `.txt` 를 `OcrParser.parse` 에 넣고 `expected.json` 의 `expect` 와 비교(name·company·title·department·phones·email).
- 이후 틀리는 명함은 사진 + 앱 캡처만 받으면 픽스처로 바로 추가.

## 1. 이름 (가장 큰 효과)
- **음절 공백**: `이 영 우`, `김 성 고`, `이 상 훈`. 줄 안에서 `([가-힣]\s?){2,4}` 패턴을 이름 후보로. 매칭 후 공백 제거.
- **같은 줄의 다른 토큰 걷어내기**: 영문명(`Lee Yeongwoo`), 직책(`위원장`, `팀원`, `대표 공인노무사`), 구분자(`•`, `·`, `|`, `/`)를 제거한 나머지가 2~4음절이면 이름.
  - `위원장 김 성 고` → 직책 위원장 + 이름 김성고
  - `팀원 • 변재희` → 직책 팀원 + 이름 변재희
  - `대표 공인노무사 곽 영 준` → 직책 "대표 공인노무사" + 이름 곽영준
- **제외**: 회사·부서·직책 사전에 걸린 단어, 로고 오인식(`게종` 같이 다른 줄에 직책+이름이 이미 있으면 무시), 주소·메일 줄.
- **우선순위**: 직책 토큰과 같은 줄 > 직책 줄 바로 위/아래 > 가장 큰 글자 줄(§5) > 첫 번째 2~4음절 한글.

## 2. 직책
- **한글 우선**. 영문 직책(Director, Partner, Manager…)은 한글 직책이 하나도 없을 때만. 영문 번역줄(`Sales Office 3 | Managing Director`)은 바로 위 한글 줄과 토큰 수가 같으면 번역으로 보고 버림.
- **구분자 줄** (`/`, `|`): `사업3본부 | 상무이사`, `제품구축팀 / 구축3파트 / 선임`, `솔루션사업본부 / 본부장 / 상무`
  → 토큰 분리 후 **직책 사전에 맞는 마지막 토큰 = 직책**, 그 앞 토큰들은 ` / ` 로 합쳐 부서.
- **사전 추가**: 상무, 상무이사, 전무, 본부장, 센터장, 실장, 파트장, 리더, 팀원, 선임, 책임, 수석, 주임, 위원장, 사무총장, 대표
- **자격명 결합**: `대표|수석|선임` + `공인노무사|변호사|세무사|회계사|변리사|법무사` → 통째로 직책.

## 3. 회사
- **회사+부서 한 줄**: `세종문화회관 재무행정팀` → 마지막 토큰이 `_deptRe`(팀|과|실|본부|센터…)면 부서, 앞부분 회사.
- **접미사 사전 추가**: 노동조합, 조합, 연맹, 재단, 공단, 공사, 진흥원, 회관, 법인(노무법인·법무법인·회계법인·세무법인 — 접두 패턴)
- **영문 로고만 있을 때**: 대문자 영단어 한 줄(`METABUILD`, `DOUZONE`)을 회사 후보로. 한글 회사명이 있으면 한글 우선(`더존비즈온` > `DOUZONE`).
- **이메일 도메인 보강**: 회사 후보가 없거나 lowConfidence면 도메인 2차 레이블(`metabuild`, `dreamsecurity`)과 로고/후보를 대소문자 무시 비교해 확정. naver/gmail/daum/hanmail/kakao 등 공용 도메인은 제외.
- **상위조직 2줄** (`한국노총 공공연맹` / `법무부노동조합`): 접미사 사전에 걸리는 줄 또는 글자가 큰 줄(§5)이 회사, 나머지 한 줄은 부서로.
- **앞 기호·숫자 제거**: `1 더존지니어스`, `N | 더존지니어스` → `^[\dA-Za-z]{1,2}\s*[|·•]?\s*` 스트립.
- 부서 후보가 하나도 없으면 "인식 불확실"이 아니라 빈값 (호연 명함 케이스).

## 4. 전화·메일·주소
- **자간 숫자**: `0 1 0 - 6 3 8 7 - 4 1 2 8` → 전처리로 "한 자리 숫자 사이 공백" 접기. (호연 명함 휴대전화 누락 원인)
- **라벨 확장**: `P`=사무실, `H`/`HP`=휴대, `A`=주소, `T`/`F`/`M`/`E` 기존. 점·공백·하이픈 구분 모두 허용 (`010.5581.6189`, `02 399 1021`).
- **한 줄 여러 필드**: `010-… · kyj@… · www.…` → `·`/`|` 로 분리해 각각 처리. `T 02 2233 5533  F 02 402 3622` 도 동일.
- **주소 두 줄 합치기**: 우편번호 5자리로 시작하거나 `시/도/구` 로 끝나는 줄 다음 줄이 `로|길 + 숫자` 를 포함하면 이어붙임.
- **이메일 오인식 교정**: 같은 명함의 website 도메인과 편집거리 ≤1 이면 website 쪽으로 (`sojongpac` → `sejongpac`). 로컬파트(`kyi`/`kyj`)는 교정 불가 → lowConfidence.

## 5. 글자 크기·위치 활용 (iOS 채널 확장)
- `VisionPlugin.recognizeText` 가 지금은 문자열만 반환. **줄별 `{text, x, y, w, h, confidence}`** 로 바꾸고 Dart 쪽 `OcrLine` 리스트를 파서에 전달 (텍스트만 받는 `parse(String)` 은 테스트용으로 유지).
- 규칙: 상단 절반에서 **가장 높은(h) 한글 줄 = 이름 1순위**, 그다음 큰 줄 = 회사. 법무부노동조합·세종문화회관처럼 텍스트만으로 애매한 경우를 정리해 줌.
- 같은 y(±h/2)에 있는 조각을 한 줄로 합치면 `위원장` + `김 성 고` 가 따로 잡히는 것도 해결.

## 6. 사용자 수정 학습 (온디바이스)
- 저장 직후 상세/수정에서 이름·회사·직책을 고치면 `ocr_hints` 테이블에 기록: `(email_domain → company)`, `(token → title)`.
- 다음 파싱에서 도메인이 같으면 회사 자동 확정, 직책 사전에 사용자 토큰 추가. 같은 회사 명함을 여러 장 받는 실제 패턴에 효과.

## 7. 보류: 온디바이스 LLM
- iOS 26+ Foundation Models(Apple Intelligence) 로 "이 텍스트에서 이름·회사·직책" 추출 가능, 서버 없음 원칙 유지. 규칙(§1~5) 적용 후 20~30장 기준 오류율 보고 결정. 구형 기기는 규칙만.
